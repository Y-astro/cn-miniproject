Keep 3 terminal tabs ready:

    cd "/run/media/astro/New Volume/Sem3/CN/miniproject"

  • Open in browser: http://localhost:8080

#### Terminal 2: Start Normal Host Agent (h1)
    cd "/run/media/astro/New Volume/Sem3/CN/miniproject"
    python3 agent/health_agent.py --id h1 --server 127.0.0.1 --port 5005 --mode real

  • What you see: Node h1 starts streaming real CPU, RAM, and procs every 1.0 second.
  • Point to Terminal 1: Node h1 appears as [UP] with NORMAL priority and sub-millisecond delay.

#### Terminal 3: Start Spiking Host Agent (h2)
    cd "/run/media/astro/New Volume/Sem3/CN/miniproject"
    python3 agent/health_agent.py --id h2 --server 127.0.0.1 --port 5005 --mode simulated --sim-pattern spike --spike-interval 3

  • What you see: Node h2 generates simulated CPU spikes to 95.0% (threshold 90.0%).
  • Point to Terminal 1: Immediate critical alert fires:
    [ALERT] [CRITICAL] Node 'h2' cpu_percent=95.0 (threshold=90.0) Latency=0.23ms
  • Point out: Socket marks IP_TOS = 0xB8 (DSCP 46 EF), routed to high-priority Queue 2!

OPTION 3: FULL LIVE MININET SDN EMULATION (FINDING 3 - IF ROOT AVAILABLE)
--------------------------------------------------------------------------------

Use this if the teacher asks to see the live Mininet virtual network topology:

#### Step 1: Start Ryu OpenFlow 1.3 Controller (Terminal 1)
    cd "/run/media/astro/New Volume/Sem3/CN/miniproject"
    ryu-manager sdn/ryu_controller.py --verbose

  • What you see: Controller initializes, starts periodic port/flow stats polling, and listens on port 6633.

#### Step 2: Launch Mininet Topology with HTB QoS Queues (Terminal 2)
    cd "/run/media/astro/New Volume/Sem3/CN/miniproject"
    sudo -E python3 sdn/topology.py --hosts 5 --interval 1.0

  • What you see: Mininet creates switch s1, hosts h1..h5, server h_server (10.0.0.100), configures OVS HTB queues (Queue 0, 1, 2) on the 10 Mbps bottleneck link, connects to Ryu, and drops you into the `mininet>` prompt.

#### Step 3: Trigger 12 Mbps Cross-Traffic Burst in Mininet CLI
  In the `mininet>` prompt, inject a 12 Mbps UDP background flood from h3 to h_server:
    mininet> h3 iperf -u -c 10.0.0.100 -b 12M -t 10

  • What you see in Terminal 1 (Ryu log):
    [SDN CONGESTION ALERT] Port 1 on switch 1 TX rate 9.60 Mbps >= 80% capacity!
    [DYNAMIC SDN ACTION] Switch 1 Port 1: Installed dynamic QoS throttle rule (Priority=80, Queue=0, idle_timeout=15s) to protect monitoring queues!

#### Step 4: Inspect Live OpenFlow Flow Rules & QoS Queues (Terminal 3)
  Run these commands to inspect hardware switch state:

  • View Active Flow Entries & Byte Counters:
    sudo ovs-ofctl -O OpenFlow13 dump-flows s1

  • View HTB Queue Packet / Byte Counters (Queue 0 vs 1 vs 2):
    sudo ovs-ofctl -O OpenFlow13 queue-stats s1

  • View Switch Port Statistics:
    sudo ovs-ofctl -O OpenFlow13 dump-ports s1

EMERGENCY UTILITY & TROUBLESHOOTING COMMANDS
--------------------------------------------------------------------------------
• Clean up Mininet if it crashed or hung:
    sudo mn -c

• Verify UDP port 5005 is active / listening:
    ss -u -l -n -p | grep 5005

• Check and kill any lingering Python agent/server processes:
    pkill -f "monitor_server.py"
    pkill -f "health_agent.py"

• Run full test suite with coverage report:
    pytest tests/ -v --cov=common --cov=server --cov=agent --cov=sdn --cov-report=term-missing
